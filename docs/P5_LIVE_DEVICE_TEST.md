# P5 一加 11 实时字幕与 IPC 验证

## 目的

验证 0.7.x 只在用户启动实时模式后接受微信读书 10.2.2 的签名调用，并把 P4 当前项显示在悬浮窗。日志只保留状态、序号和长度，不导出正文。

## 操作步骤

1. 经用户许可安装当前 0.7.x；完全关闭并重新打开微信读书，使新 Hook 代码生效。
2. 打开 WeReadLyrics，确认悬浮权限仍有效，点击“启动实时字幕”。通知应显示实时模式，未朗读时屏幕上没有字幕条。
3. 打开微信读书开始 AI 朗读，观察字幕是否随实际句子更新；切到桌面和浏览器继续观察。
4. 暂停约 5 秒：字幕应保留并变淡，且不推进；继续后恢复正常亮度和更新。
5. 执行前跳、后跳和切章：旧字幕应立即清除，随后显示新播放项。
6. 停止朗读并等待至少 16 秒：字幕应消失，实时模式通知仍保留以等待下一次朗读。
7. 从通知或管理界面停止悬浮字幕，再次朗读：字幕不得自行出现，证明 Hook 不能后台创建服务。

## 证据与判定

保留 `IPC connected`、`IPC accepted`、`Overlay applied` 和错误类型的脱敏日志。额外检查私有 Overlay Service 不能由 shell 外部启动；Bridge 接口由非微信读书 UID 调用时必须拒绝。

- `PASS`：真实字幕关联正确；暂停、跳转、切章、停止和用户关闭均按预期；鉴权及生命周期检查通过；微信读书无可见回归。
- `PARTIAL`：主要字幕正确，但 IPC 重连、系统后台行为或个别状态异常。
- `FAIL`：未授权来源可更新字幕、正文进入日志/磁盘、旧字幕残留，或影响宿主运行。

## 当前结果

0.7.0 首次实测因重试时间哨兵减法溢出，没有发起绑定；0.7.1 修复后，日志确认 `IPC bind requested=true`、`IPC connected`，Bridge 持续接受状态并在主线程更新悬浮窗。用户确认字幕内容与当前发声一致，微信读书发声和内置高亮正常。

2026-10-13 完整交互复测中，用户确认跨桌面/其他应用显示、暂停保留、恢复更新、前后跳、切章、停止后清屏、通知保留和手动关闭后不自启均正常。脱敏日志记录到 `PAUSED`、`Resumed`、章节/会话重建、15 秒后 `IDLE`，以及用户关闭时 `IPC disconnected`；关闭后 Hook 事件继续但不再出现 `Overlay applied`。未发现 `FATAL EXCEPTION`、Hook 或 IPC 错误。

shell 显式启动私有 `OverlayService` 被系统以 `Requires permission not exported` 拒绝；随后模块无进程，残留记录为 `app=null`、`startForegroundCount=0`，证明服务未实例化。独立 UID 探针随后证明 Bridge 会丢弃非微信读书调用，详见 `P5_IPC_SECURITY_TEST.md`。

**P5 结论：`PASS`。** 模拟与真实字幕、悬浮权限、跨应用显示、IPC 鉴权及生命周期均在一加 11 上通过。0.7.2 正向回归再次确认微信读书调用被接受并更新字幕，未观察到宿主回归或崩溃。
