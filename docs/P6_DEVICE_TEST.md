# P6 一加 11 端到端与稳定性验证

## 范围与证据

使用微信读书 10.2.2、LSPosed 2.1.1（API 102）和 WeReadLyrics 0.8.0。日志仅保留状态、序号、长度和进程信息；不保存正文、书名或章节标识。人工同步结论记录观察次数与明显提前、滞后或错句次数，不虚构毫秒精度。

## 准备

1. 运行 `./scripts/check-debug-build.sh`，记录 APK 版本与 SHA-256。
2. 经用户许可覆盖安装 APK，完全关闭并重新打开微信读书。
3. 启动实时字幕和 AI 朗读，确认每个微信读书进程只出现一次 `Module loaded` 与 `Probe install complete`。
4. 记录微信读书与模块的初始 `dumpsys meminfo` 摘要，并启动脱敏日志采集。

## 功能与恢复场景

1. 连续执行三次启动、停止实时字幕；每次均应正确显示和移除，不出现重复窗口或通知。
2. 播放、暂停、继续、前跳、后跳、切章及切换前后台；记录至少 20 次文本切换，核对字幕与实际发声。
3. 分别选择微信读书提供的最低和最高倍速，各观察至少五次文本切换；不得残留旧句或影响内置高亮。
4. 播放中锁屏约 30 秒再解锁。记录锁屏期间系统是否显示覆盖层；解锁后字幕必须恢复到当前发声内容，不保留锁屏前旧句。
5. 在未缓存段落播放时由用户关闭当前网络约 20 秒，再恢复网络。记录朗读是继续、缓冲还是停止；恢复后字幕必须跟随实际行为，不得自行推进。
6. 字幕可见时，经用户许可强制停止微信读书。Binder 日志应出现 `IPC source disconnected`，字幕应立即清除；重新打开并播放后应重新注入一次并恢复字幕。
7. 连续播放至少 30 分钟，期间至少执行一次暂停/恢复、前后台切换和倍速变化。结束后再次记录内存摘要。

## 判定

- 无 `FATAL EXCEPTION`、Hook/IPC 初始化失败、重复窗口或严重宿主回归。
- 正常停止最迟在当前 15 秒清理窗口后隐藏；宿主进程退出通过 Binder 死亡通知清屏。
- 日志中的 `Overlay applied` 只对应文字、透明度或显隐变化；相同视觉状态不重复重绘。
- 资源摘要用于发现持续增长迹象；单次 PSS 差异不单独宣称存在或不存在内存泄漏。

完成全部场景后给出 `PASS`、`PARTIAL` 或 `FAIL`，并列出未覆盖的系统行为。

## 当前结果

2026-10-13 已安装 0.8.0（versionCode 10）。播放期间强制停止微信读书后，设备确认宿主 PID 消失；同一毫秒内模块先记录 `IPC source disconnected`，再应用 `IDLE` 空状态，用户确认字幕正常消失。模块前台服务保持运行且未崩溃。重新打开微信读书后 IPC 自动恢复，用户确认字幕重新出现且内容正常。

重绘去重日志显示，相邻的预备/播放更新仍由 Bridge 按序接受，但相同视觉状态只产生一次 `Overlay applied`。初始内存摘要已采集；每进程 Hook 安装次数、锁屏、网络、倍速及连续运行仍待后续场景确认。当前 P6 结论为 `PARTIAL`。

用户随后确认三次实时字幕启动/停止、最低与最高倍速、跨应用、锁屏约 30 秒后恢复，以及断网约 20 秒后恢复均正常；没有观察到错句、明显提前/滞后、重复窗口或通知。断网期间微信读书采用的具体播放策略未单独记录，因此只判定模块行为与实际发声一致。日志覆盖多个暂停/恢复和连续文本状态，未出现 `FATAL EXCEPTION`、Hook 安装失败或 IPC 发布失败。

功能场景结束时模块 PSS 约 43 MB；这是单次中途样本。30 分钟连续运行、结束内存对比及从进程启动开始的 Hook 安装计数仍待完成。
