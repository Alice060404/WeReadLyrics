# P3 一加 11 只读探测

## 目的与边界

验证微信读书 10.2.2 的现有朗读高亮事件是否与实际 AI 语音同步，并用书籍播放器控制入口区分开始、暂停、继续、停止、跳句和 seek。模块不改变参数、返回值或播放流程；不记录正文、书名、bookId 或原始 utteranceId。日志只含事件类型、单调序号、相对毫秒、文本长度、进程内随机盐短哈希、字符范围和线程名。

安装 0.4.0 APK 和重新启动微信读书前须取得用户许可。发现闪退、卡顿、朗读异常或日志包含正文时立即停止，禁用模块并重新打开微信读书。

## 操作步骤

1. 更新安装 `app/build/outputs/apk/debug/app-debug.apk`，确认 LSPosed 作用域仍只有微信读书。
2. 用户关闭并重新打开微信读书；确认日志显示高亮及书籍播放器控制共十个 Hook 安装完成，且没有 `Probe install failed`。
3. 清晰报出“开始”，随后启动 AI 朗读并连续播放约 60 秒。
4. 在一句正在发声时报出“暂停”并暂停约 5 秒，再报出“继续”并恢复。
5. 等待自然换句；随后报出“停止”并停止朗读。
6. 导出这段时间的 `WeReadLyrics` 日志。只保留探针字段，不保存其他设备日志或书籍正文。

## 扩展场景

基础控制通过后，在一次连续 2—3 分钟的朗读中依次执行：前跳、后跳、切到下一章、切到后台再返回，以及切换一个可用倍速。每次操作后至少等待一句完整语音，人工确认实际发声与内置高亮仍一致。记录控制事件、高亮范围是否重置或继续，以及是否发生崩溃、卡顿、重复播放或旧章节高亮残留。

## 判定

- `PASS`：高亮 start 随当前发声推进，书籍播放器控制事件能区分暂停、继续和停止；暂停期间高亮不推进，继续后恢复，短哈希和范围能区分换句，且无宿主回归。
- `PARTIAL`：能观察文本/进度，但事件提前、滞后、缺少生命周期或不能可靠区分当前播放项。
- `FAIL`：候选方法未调用、只反映预取、正文泄漏或影响微信读书行为。

本轮人工口令只能提供粗粒度时间参照，不宣称毫秒级准确度。
